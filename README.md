# HH.ru Vacancy Parser

Консольное приложение для получения информации о компаниях и их вакансиях с использованием API [hh.ru](https://hh.ru/), сохранения данных в PostgreSQL и выполнения аналитических запросов к базе данных.

Проект разработан в учебных целях для практики работы с REST API, PostgreSQL, SQL-запросами, обработкой исключений и взаимодействием Python-приложения с базой данных.

> **Примечание:** доступ к API hh.ru в настоящее время может быть ограничен. Поэтому в проекте предусмотрен режим загрузки заранее подготовленных тестовых данных из JSON-файла. Это позволяет полностью продемонстрировать работу приложения даже при недоступности API.

---

## Возможности

Приложение позволяет:

- создавать базу данных PostgreSQL;
- создавать необходимые таблицы;
- получать список работодателей через API hh.ru;
- получать вакансии выбранных работодателей;
- сохранять компании и вакансии в PostgreSQL;
- загружать тестовые данные из JSON-файла;
- проверять структуру тестовых данных перед загрузкой;
- выполнять SQL-запросы к сохранённым данным;
- получать список компаний и количество их вакансий;
- просматривать все вакансии;
- рассчитывать среднюю зарплату по компаниям;
- находить вакансии с зарплатой выше средней;
- искать вакансии по ключевому слову;
- обрабатывать ошибки API, файлов и структуры JSON без аварийного завершения программы.

## Архитектура проекта

Проект разделён на несколько логических компонентов.

### *APIhh.py*

Отвечает за взаимодействие с API hh.ru.

Основные методы:

**get_employers()** - Получает информацию о работодателях.

**get_vacancies()** - Получает список вакансий конкретного работодателя.

Для ошибок API используется собственное исключение:

```
class HHApiError(Exception):
    """Ошибка при работе с API hh.ru."""
```

### *DBWorker.py*

Отвечает за создание базы данных, таблиц и загрузку данных.

Основные задачи:

создание базы данных;
создание таблиц companies и vacancies;
загрузка данных из API;
загрузка тестовых данных;
проверка структуры JSON;
управление транзакциями.

Для ошибок тестовых данных используется:
```
class TestDataError(Exception):
    """Ошибка загрузки тестовых данных."""
```

### *DBManager.py*

Отвечает за получение и анализ данных из PostgreSQL.

Реализованы следующие запросы:

компании и количество вакансий;
список вакансий;
средняя зарплата;
вакансии с зарплатой выше средней;
поиск вакансий по ключевому слову.

### *user_interface.py*

Содержит консольный интерфейс приложения.

Пользователь взаимодействует с программой через меню:
```
Выберите действие:
1 - Создать базу данных
2 - Загрузить тестовые данные
3 - Загрузить данные с HH.ru
4 - Далее
0 - Выход
```
После перехода к работе с БД:
```
Выберите действие:
1 - Список компаний и количество вакансий
2 - Все вакансии
3 - Средняя зарплата по компаниям
4 - Вакансии с зарплатой выше средней
5 - Вакансии по ключевому слову
0 - Выход
База данных
```
В проекте используются две таблицы.

companies:
 - Поле:	Тип:	Описание
 - company_id:	INT:	ID компании (Primary Key)
 - name:	VARCHAR(50):	Название компании
 - website:	TEXT:	Ссылка на компанию
 - vacancies:	INT:	Количество открытых вакансий

vacancies:
 - Поле:	Тип:	Описание
 - company_id:	INT:	ID компании
 - vacancy_id:	INT:	ID вакансии
 - name:	VARCHAR(100):	Название вакансии
 - published_at:	DATE:	Дата публикации
 - salary_from:	INT:	Нижняя граница зарплаты
 - area:	VARCHAR(50):	Регион
 - type:	VARCHAR(50):	Тип занятости
 - website:	TEXT:	Ссылка на вакансию

company_id является внешним ключом:
company_id REFERENCES companies(company_id)

Тестовые данные позволяют использовать все функции DBManager, не обращаясь к API hh.ru.

### *Проверка тестовых данных*

Перед загрузкой JSON выполняется проверка его структуры.

Для компаний обязательны поля:
```
{
    "company_id",
    "name",
    "website",
    "vacancies",
}
```
Для вакансий:
```
{
    "company_id",
    "vacancy_id",
    "name",
    "published_at",
    "salary_from",
    "area",
    "type",
    "website",
}
```
Проверка выполняется с использованием операций над множествами:
```
missing_fields = REQUIRED_VACANCY_FIELDS - vacancy.keys()
```
Если обязательное поле отсутствует, загрузка прекращается до изменения базы данных.

Например:
```
Ошибка загрузки тестовых данных:
Вакансия №10: отсутствуют поля: company_id.
```
### *Обработка ошибок*

В проекте предусмотрена обработка основных ошибок.

#### Ошибки API

Например, при получении ответа: 403 Forbidden

программа выводит:
```
Ошибка загрузки данных с HH.ru:
API hh.ru вернул ошибку: 403
```
Используется исключение:
```
HHApiError
Ошибка JSON
```
Если JSON имеет некорректный синтаксис:
```
Ошибка загрузки тестовых данных:
Ошибка формата JSON: строка 133, столбец 19
Отсутствующий файл
```
Если test_data.json отсутствует:
```
Ошибка загрузки тестовых данных:
Файл тестовых данных не найден:
D:\Projects\HomeWorks\Proj_HH\data\test_data.json
Неверная структура JSON
```
Если в объекте отсутствует обязательное поле:
```
Ошибка загрузки тестовых данных:
Вакансия №10: отсутствуют поля: company_id.
Безопасность загрузки данных
```
* Перед загрузкой тестовых данных выполняется их проверка.

Только после успешной валидации выполняется очистка таблиц:
```
TRUNCATE TABLE vacancies, companies CASCADE
```
Загрузка данных выполняется внутри транзакции.

При возникновении ошибки:
```
self.conn.rollback()
```
При успешной загрузке:
```
self.conn.commit()
```
Таким образом, ошибка загрузки тестовых данных не приводит к появлению частично загруженной базы.

После выбора:
```

1. Компании и количество вакансий

Выводится список компаний с количеством вакансий.

Сортировка выполняется по количеству вакансий:
```

```

2. Все вакансии

Выводятся:

вакансия;

ссылка на вакансию.

3. Средняя зарплата по компаниям

Для каждой компании рассчитывается средняя зарплата:
```
AVG(vac.salary_from)
```
Результаты сортируются по средней зарплате.

4. Вакансии с зарплатой выше средней

Выводятся вакансии, зарплата которых не ниже средней зарплаты по всем вакансиям.

5. Поиск по ключевому слову

Пользователь вводит ключевое слово.

Поиск выполняется без учёта регистра:
```
LOWER(vac.name) LIKE LOWER(%s)

## Особенности проекта
### *Отделение логики от интерфейса*

Работа с API, базой данных и пользовательским интерфейсом разделена по отдельным модулям.

### *Работа с PostgreSQL*

Используется psycopg2 для подключения к PostgreSQL и выполнения SQL-запросов.

### *Параметризованные запросы*

Пользовательские данные передаются в SQL через параметры:
```
self.cur.execute(
    """
    ...
    WHERE LOWER(vac.name) LIKE LOWER(%s)
    """,
    (f"%{keyword}%",),
)
```

### *Транзакции*

При загрузке тестовых данных используется `commit()/rollback()`, что предотвращает сохранение частично загруженных данных.

### *Собственные исключения*

Для разных частей приложения используются отдельные типы ошибок:
```
HHApiError
TestDataError
```
Это позволяет обрабатывать ошибки на уровне пользовательского интерфейса без вывода необработанного traceback.

### *Ограничение API hh.ru*

Проект изначально рассчитан на получение данных через API hh.ru.

Однако доступ к API может быть ограничен сервером hh.ru, в том числе с ответом:

`403 Forbidden`

Поэтому для демонстрации функциональности предусмотрен автономный режим с тестовыми данными.

Это позволяет продемонстрировать:

 - создание БД;
 - загрузку данных;
 - связи между таблицами;
 - SQL-запросы;
 - расчёт средней зарплаты;
 - поиск;
 - обработку ошибок.

без зависимости от доступности внешнего API.
